# Экраны: Администрация_ОП + шаблон карнета

## A. Шаблон `03_Карнет.xlsx`

Лист: `Карнет`

| # | Колонка | Тип | Обязательно | Описание |
|---|---------|-----|-------------|----------|
| 1 | `tab_no` | text | да | Табельный, ключ к Базе |
| 2 | `fio` | text | да | Контроль совпадения с Базой |
| 3 | `site_code` | text | да | Код: `ТИ` / `АКЗ` / `ЛС` / `МБР` … |
| 4 | `site_name` | text | да | Полное имя участка |
| 5 | `position_fact` | text | нет | Фактическая должность с площадки |
| 6 | `primary_tab` | text | да* | Таб. № основного оценивающего |
| 7 | `primary_fio` | text | да* | ФИО (контроль); роль берётся из `02_Пользователи` |
| 8 | `status` | enum | да | `Работает` / `На межвахте` / `Не оценивается` |
| 9 | `shift_start` | date | нет | Дата начала вахты |
| 10 | `last_final_score` | number | нет | Прошлый итог (информативно) |
| 11 | `evaluate` | enum | да | `yes` / `no` — участвует ли в текущем периоде |
| 12 | `dual_enabled` | enum | нет | `no` по умолчанию; `yes` только для массового включения |
| 13 | `secondary_tab` | text | если dual=yes | Таб. № второго оценивающего |
| 14 | `secondary_fio` | text | если dual=yes | ФИО второго (контроль) |

\* Если сотрудник на межвахте / ещё не на ОП — **primary можно не заполнять**, `evaluate=no`.

### Правила импорта карнета

1. `tab_no` ∈ База, ФИО совпало (иначе строка → ошибка).
   **Исключение:** `tab_no=Кандидат` — в Базе может не быть; строка принимается с `evaluate=no`.
2. Пустой `primary` допустим → `evaluate=no` (ожидание назначения после приезда).
3. Если primary заполнен → ∈ Пользователи, Активен, роль ∈ {Мастер, Производитель работ}.
4. Нельзя primary = Начальник участка / Admin.
5. Кандидаты: всегда `evaluate=no`, без primary/dual, пока нет трудоустройства.
6. Если `dual_enabled=yes` → secondary обязателен, роль ∈ {Мастер, ПР}, ≠ primary, желательно другая роль.
7. Пустой `dual_enabled` = `no`.
8. Повторный импорт: upsert по `tab_no` + текущий период (для кандидатов — по связке fio до появления табельного).
9. Назначение primary по приезду — основной сценарий **UI Админ_ОП** (Excel — для массовых правок).

## B. Экраны Администрация_ОП

### B1. Дашборд периода
- Выбор периода (`2026-H2`)
- Карточки: всего к оценке / анкет сдано / dual включён / без primary / открытые тикеты
- Кнопки: «Импорт Excel», «Открыть назначения», «Реестр»

### B2. Назначения (главная таблица)
Фильтры: участок, status, evaluate, dual, «без primary», ФИО/таб.№.

Колонки таблицы:

| Колонка | Редактирование |
|---------|----------------|
| Таб.№, ФИО | read-only (из Базы) |
| Участок | select / смена |
| Должность факт | text |
| Primary (таб+ФИО+роль) | select из пользователей master/foreman |
| Dual | toggle |
| Secondary | select (активен только если dual on) |
| Evaluate | toggle |
| Статус анкеты primary | read-only |
| Статус анкеты secondary | read-only |
| Действия | «Открыть карточку» |

Массовые действия: сменить участок выбранным; выставить evaluate yes/no.

### B3. Карточка сотрудника
- Блок из Базы: должность, приём, стаж, ставка, rate_updated_at (если пусто — предупреждение)
- Редактирование Базы Админ_ОП (если запись создана/дополнена вручную)
- Блок площадки: участок, position_fact, status, shift_start
- Блок плановой оценки: primary, dual toggle, secondary, evaluate
- Кнопки: **«Срочная оценка»**, **«Заместить на период»**
- История назначений / оценок / срочных / замещений
- Лента событий (event log) по сотруднику
- «Добавить в Базу» / «Добавить в карнет периода»

### B3a. Срочная оценка (мастер-экран)
1. Поиск сотрудника **только в Базе** (если кандидат ещё не в Базе — сначала «Оформить в Базу»: tab_no, fio, …).
2. Мультивыбор оценивающих: Мастер/ПР, **один или несколько**.
3. Комментарий админа («нужно сегодня», причина).
4. «Отправить» → у каждого в ЛК появляется задача со статусом Срочно.
5. Мониторинг: кто сдал / кто нет; закрыть заявку / напомнить.

### B3b. Замещение на период
1. Выбор текущего primary с открытыми анкетами.
2. Назначить заместителя (мастер/ПР), даты с–по, причина.
3. Заместитель видит список как primary, **без** чужих черновиков/оценок.
4. Очередь эскалаций: primary не заходил ≥ 3 дня.

### B4. Импорт Excel
- Выбор типа: База / Пользователи / Карнет / Квыр
- Upload → превью (N строк) → «Применить»
- Результат: added / updated / skipped / errors (скачать CSV ошибок)
- Ручные записи Админ_ОП в Базе **не затираются вслепую**: конфликт tab_no → отчёт, стратегия merge/skip

### B5. Пользователи ЛК (ОП)
- Список master/foreman/site_chief/admin_op
- Создание / деактивация / сброс пароля
- Привязка к site_code

### B6. Реестр
- Как в `Реестр_оценок`: блоки оценок + Квыр + итог + статус
- Отдельный признак/фильтр **Срочная**
- При N оценивающих — итог = среднее сданных по заявке (детали в раскрытии строки)
- Подсветка ЧСТ ≥ 6 мес., экспорт Excel
- Тяжёлые выборки — через Registry API (read-only), не Field API

### B7. Тикеты «Ошибка в списке»
- Очередь от мастеров/ПР: сотрудник не мой / не тот участок / уволен
- Статусы: new / in_progress / done
- Из тикета — переход в карточку назначения

### B8. База сотрудников (отдельный список)
- Все, кого загрузили или внесли Администрацией
- Фильтры: есть/нет в карнете периода, кандидат→сотрудник, без tab_no
- Создание вручную, редактирование, привязка к ОП

## C. Минимальный happy-path для теста

1. Импорт Базы + Пользователей + Карнета.
2. Мастер сдаёт плановую single-анкету **офлайн**, затем синк.
3. Админ_ОП оформляет вчерашнего кандидата в Базу (tab_no).
4. «Срочная оценка» → два мастера/ПР → оба сдают вслепую.
5. Замещение primary на период → заместитель закрывает висящие анкеты.
6. Строка в реестре; event log показывает цепочку изменений.
7. Нач. участка / Квыр → финальный балл (если применимо).

## D. Field PWA (мастер/ПР) — кратко

- Installable PWA, IndexedDB: список + черновики + outbox.
- Автосинк при online; индикатор «не отправлено: N».
- Конфликт назначения → diff → перезаполнить / отменить черновик.
- Срочные и плановые задачи в одном списке с бейджами.
